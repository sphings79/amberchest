**A sixth beta of 2.2.0.** It is not the newest stable release and it does not
move `latest`: the container image is
`ghcr.io/sphings79/amberchest:2.2.0-beta.6`. Please do not run it on an archive
you cannot afford to have a problem with.

This one is about finding out what went wrong, after reports on #3 and #9. It
adds a log setting to the interface, an optional log file, and says in the log
why the server removal leaves a message alone. Everything else is as in beta 5.

What it needs from you, if you use the removal: run it again where messages
were left alone and send me the lines "... is not the archived message" from
the log (see below).

Report what you find in the issue or at
https://github.com/sphings79/amberchest/issues.

## The log level is a setting

Until now the level could only be set with `AMBERCHEST_LOG_LEVEL` in the
container, so the desktop app always ran at "info". **Settings → Log** has the
level now: debug, info, warnings or errors. It applies at once, without a
restart, in the desktop app and in the container, and it is saved.

"As started" leaves the level to the start-up, which is
`AMBERCHEST_LOG_LEVEL` in the container and "info" otherwise. A level chosen in
the interface replaces it.

Debug writes a lot, and the log view in the interface keeps only the last 2000
entries. For a long run use the file below.

## An optional log file

Switch on **Also write the log to a file** and the log goes to
`logs/amberchest.log` in the folder that holds the configuration (`/config/logs`
in the container). It holds the same lines as the container's output, with the
stack trace of an error below its line, and obeys the level above.

The file cannot fill the disk: it is replaced when it reaches 50 MB, and three
files are kept, 150 MB at most. It is readable by the user the program runs as
and nobody else. The log page gets a **Download the log file** button while the
file is on; the read-only login cannot use it.

A debug log names folders and files, so look through it before you attach it
to a report.

## The removal says why it leaves a message alone

For mail that the server holds under the right UID but with different details
than when it was archived ("not the archived message" in the result), the log
now shows, for the first five in each folder, which parts differ: the date and
the size as numbers, and for the message ID, the sender and the subject only
whether they match. Subject and addresses are not written to the log.

> INBOX UID 4711 is not the archived message: differs in size (stored 5120,
> server 5163)

The summary at the end counts messages that are no longer on the server as
left alone as well, so it agrees with the line per folder.
