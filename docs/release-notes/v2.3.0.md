An account can now be kept as a passive archive. Nothing else about backups
changed.

## Passive archive

When a mailbox is about to be deleted at the provider, run one last backup and
press **Make passive** on the account. AmberChest then never connects to that
server again: no scheduled backups, no recurring errors. The archive stays what
it was: browse, search, export and restore its mail to another account as
before. The stored password or sign-in is kept, and **Reactivate** brings the
account back at any time and tests the connection right away.

Switching checks the last backup first. If it never ran, did not finish
cleanly, or is older than seven days, you can run a final backup and switch
when it ends clean, or switch anyway.

A passive account refuses everything that would reach the server: a backup,
the folder list, the comparison with the server in Verify (the check of the
files stays), removal from the server and adopting with a server query.
Restore is not blocked, because it works with whatever server details you
enter and cannot tell whether they belong to this account.

In Home Assistant the account gets a **Passive archive** sensor, and the AI
connection lists it with `passive: true` (#12).

## Smaller things

- A failed connection test, a failed folder list and a failed reactivation now
  read in the language of the interface for the common causes (server not
  found, connection refused, timeout, certificate). Any other error keeps the
  text the server sent.
- A browser that refuses the service worker no longer logs an unhandled error.
