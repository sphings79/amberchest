A bug fix for the log. Nothing else changed.

## What was wrong

When a backup failed with "Connection not available", the log said nothing
more, so there was no way to tell a server that hung up on purpose (a limit, a
throttle) from a connection that simply broke. Two things were missing:

- The library that talks to the mail server knows why a connection ended - the
  text the server sent when it closed it, and the command that was running -
  but the message dropped both.
- The container's log (`docker logs`) printed the time, the level and the
  message of each entry, and left out the stack trace that comes with a failed
  backup.

## What changed

A lost connection now says what the server told and what was running, as in
"Connection not available (server said: ..., during FETCH)". The stack trace of
a failed backup is printed below its log line in the container's log.

This does not fix a backup that fails for that reason; it makes the reason
visible (#9).
