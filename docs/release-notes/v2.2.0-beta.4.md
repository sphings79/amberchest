**A fourth beta of 2.2.0.** It is not the newest stable release and it does not
move `latest`: the container image is
`ghcr.io/sphings79/amberchest:2.2.0-beta.4`. Please do not run it on an archive
you cannot afford to have a problem with.

This one fixes how "Throw out of the archive" treats mail that is in more than
one place, which was reported in #4. It also contains everything from the
earlier betas: the read-only login (beta 1), selecting several messages
(beta 2) and removing archived mail from the server (beta 3). The notes of beta
3 are worth a read before you switch that on, because it deletes on the server.

What it needs from you is a test, above all of:

- throwing a message out that is shown in several folders, with "Store a
  message only once" on (Gmail): is the file gone, and does the next backup
  leave it out of every folder?
- throwing out a mail the server has already lost (the filter that includes
  deleted mail): is the file gone from the `_deleted` folder?
- the switch "Also the copies in other folders" in the dialog of the bulk
  action, on and off.

Report what you find in the issue or at
https://github.com/sphings79/amberchest/issues.

## Throwing a message out removes every copy of it

A mail that is stored once and shown in several folders, as Gmail does it, is
one file with several places. Throwing it out of one folder used to leave the
file with the others, which is the wrong answer when the point is to free
space.

Now all of its places go, by default, and each one keeps its own record that
the mail was thrown out on purpose. The records have to be per folder: the
backup looks at every folder, and one without a record would fetch the mail
again from there. The file is deleted once.

- On a single message the right click menu always takes all places and tells
  you how many copies in other folders went with it.
- The dialog of the selection action has a switch, **"Also the copies in other
  folders"**, on by default. Off, only the copy in the chosen folder goes, and
  the file stays as long as another folder shows it - what it did before.
- An index rebuilt from the files keeps the record of every folder.

## A mail the server has lost is deleted too

Mail that was deleted on the server is kept in the `_deleted` folder of the
account. Throwing such a message out marked it as thrown out, but looked for
its file in the folder itself, deleted nothing, and left the file where no
list showed it. A discarded folder left its `_deleted` copy behind in the same
way. Both now delete the file.

This has been in the program since the right click menu was added in 2.1.0. If
you have used it on mail from the `_deleted` filter, "Check archive" lists the
files that stayed as files that no index entry points at, and they are safe to
delete.
