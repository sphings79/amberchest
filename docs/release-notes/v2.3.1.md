Big folders are scanned more reliably, messages deleted on the server are easy
to find, and the mailbox name is shown in more places.

## Big folders are scanned by the UIDs that exist

A folder with many messages is read in blocks of UIDs. Those blocks were cut
from the whole range `1` to `UIDNEXT`, so a folder that had lost most of its
mail (UIDs far apart) cost thousands of empty requests, and a host that limits
how long a connection may live closed it before the scan was done.

The folder's UIDs are now asked for first, and the blocks are made of UIDs that
exist. A folder that fits in one block is read with a single request, however
high its UIDs are (#13).

## Messages deleted on the server are easy to recognise and to browse

With "move to _deleted" the archive keeps what vanished from the server.

- In the search and in the mailbox, such a message carries a "deleted on
  server" badge.
- The setting "Messages deleted on the server" is now a choice of three: leave
  out (the default), show along with the rest, or show only these. "Show only
  these" lists everything the server lost, across all folders.
- The folder numbers and the mailbox total follow that setting.
- The MCP search tool has a matching `only_deleted` option (#14).

## Throwing out a mail that is deleted on the server leaves nothing behind

"Throw out of the archive" on a mail that is already deleted on the server now
removes it for good instead of creating an entry under "Discarded". Entries
that are already there are cleaned up by the next backup once the mail is gone
from the server as well, or its whole folder is (#16).

## The mailbox name is shown in Search, Discarded and the mail view

In the search results and in the "Discarded" list, each mail shows
`Mailbox › Folder`, after the sender in both lists. The mail header has a new
"Account" row above "Folder" (#15).
