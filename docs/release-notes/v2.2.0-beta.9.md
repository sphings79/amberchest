**A ninth beta of 2.2.0.** It is not the newest stable release and it does not
move `latest`: the container image is
`ghcr.io/sphings79/amberchest:2.2.0-beta.9`. Please do not run it on an archive
you cannot afford to have a problem with.

This one makes the backup of a big mailbox lighter on the server, after #9, and
adds a way to store mail once that an archive holds twice.

What it needs from you, if you have a mailbox of tens of thousands of messages:
a backup of it, and what the log shows at the debug level (Settings -> Log).

Report what you find in the issue or at
https://github.com/sphings79/amberchest/issues.

---

## A backup no longer reads every message each time

The scan of a folder asked the server for the envelope of every message at
every run. It now asks which UIDs the folder holds (one cheap command), reads
the envelope of the new ones only, and takes the flags of the rest. An envelope
cannot change under a UID, so what the archive stored stands in for it. Deleted
mail and changed flags are found as before.

A folder is read in full when its UIDVALIDITY is new or changed, and in any
case once a week. The debug log tells scan blocks (envelopes) from flag blocks.

## Store a message only once

"Store a message only once" is on for every new account. Accounts that exist
keep their setting. For an archive that already holds mail twice - Gmail shows
a mail in its folder and in "All Mail" - there is **"Store duplicates once
..."** on the account card. It shows how many copies it can merge and how much
space that frees, then replaces each second copy by a link to the first. A copy
goes only when both files can be read and match the checksum taken at download;
anything else is left alone and counted. Stopping early is safe.

## Also

- A message with an empty `Content-Type` header on one of its parts
  (`Content-Type: ; name="..."`) was left out of the search index, because the
  parser reports no type for it. It is indexed now.

## Not tested against a real mailbox yet

The new scan and the merging of copies are covered by tests against a stand-in
for the server and a temporary archive. This beta is where they meet a real
Gmail account and a real archive.
