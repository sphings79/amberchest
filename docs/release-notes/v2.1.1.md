A security fix. If your instance can be reached from a network you do not
fully trust, update now.

## What was wrong

The web interface and the API are protected by a password, and every request
to `/api/...` has to carry a session token. The check decided whether a
request was an API request by looking at the URL as it was written. The router
that picks the handler decodes percent escapes first, so a request for
`/%61pi/settings` was not recognised as an API request, passed the check
without a token, and was then served by the `/api/settings` handler.

Anyone who could reach the port could therefore call any API route without
logging in: read the settings, list the accounts, search and read archived
mail, download files, and use the administrative routes. With the
configuration unlocked - which is the normal state of a container - nothing
else stood in the way.

This affects every release up to and including 2.1.0, wherever the interface
is protected by `AMBERCHEST_UI_PASSWORD`. The desktop app listens on the
loopback address only, but the same applies to other programs on that machine.
A Home Assistant add-on without an interface password only answers the
supervisor and was not reachable this way.

## What changed

The check now looks at the path the way the router does, so every spelling of
an API path needs a valid token. A path that cannot be decoded is refused.
Tests cover the encoded spellings.

## What you should do

1. Update to 2.1.1.
2. If the port was reachable from outside your own network, treat the
   instance as having been readable: change the interface password, create a
   new MCP token, and consider changing the passwords of the mailboxes that
   were archived. Requests that used the trick show up in a reverse proxy's
   access log as paths starting with `/%` followed by hex digits, in place of
   `/api`.
3. Do not rely on the interface password alone for an instance on the open
   internet. Put it behind a reverse proxy with its own authentication or a VPN.

## Also in this release

- Dependencies were brought up to their latest versions within the ranges the
  project already allowed. This clears the advisories `npm audit` reported for
  the server's runtime dependencies (fastify, mailparser with nodemailer,
  fast-uri, ip-address). One advisory remains in the build tooling of the
  desktop app (electron-builder), which does not ship in the app.
- The server package now has a test script, so its tests run in CI together
  with the rest.
