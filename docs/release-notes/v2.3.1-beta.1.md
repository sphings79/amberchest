**A first beta of 2.3.1.** It is not the newest stable release and it does not
move `latest`: the container image is
`ghcr.io/sphings79/amberchest:2.3.1-beta.1`. Please do not run it on an archive
you cannot afford to have a problem with.

This one changes how a big folder is scanned, after #13.

What it needs from you, if a backup still pauses with "Connection not
available": set the log level to debug and send the lines that read
`scan block N/M (UID ...)`, so it can be seen how far the scan got and how long
each block took.

Report what you find in the issue or at
https://github.com/sphings79/amberchest/issues.

---

## Big folders are scanned by the UIDs that exist

A folder with many messages is read in blocks of UIDs. Those blocks were cut
from the whole range `1` to `UIDNEXT`, so a folder that had lost most of its
mail (UIDs far apart) cost thousands of empty requests, and a host that limits
how long a connection may live closed it before the scan was done. The next run
started over and met the same limit.

The folder's UIDs are now asked for first, and the blocks are made of UIDs that
exist. A folder that fits in one block is read with a single request, however
high its UIDs are.

A scan that is cut off still starts again from the beginning; whether that needs
more is for this beta to show.
